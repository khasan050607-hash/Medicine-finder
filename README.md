# Medicine Finder — Task 1: Project Setup & Navigation

## এই ধাপে যা তৈরি হয়েছে
- Flutter project structure (`lib/main.dart`, `lib/screens/`, `lib/theme/`)
- Home screen — ৪টা মডিউলের কার্ড মেনু:
  - Medicine খুঁজুন (Search)
  - নতুন Medicine যোগ করুন (Add)
  - সব Medicine দেখুন (List)
  - Camera দিয়ে খুঁজুন (Camera Match — এখন লকড/প্লেসহোল্ডার)
- প্রতিটা স্ক্রিন এখন খালি/প্লেসহোল্ডার — পরের টাস্কগুলোতে আসল ফাংশনালিটি যোগ হবে

## নিজের কম্পিউটারে চালানোর নিয়ম
**গুরুত্বপূর্ণ:** এখানে শুধু `lib/` কোড ও `pubspec.yaml` দেওয়া আছে — Android/iOS
এর প্ল্যাটফর্ম ফোল্ডার (`android/`, `ios/`) নেই, কারণ সেগুলো Flutter টুল
দিয়ে জেনারেট করতে হয়।

1. Flutter SDK ইনস্টল থাকতে হবে ([flutter.dev](https://flutter.dev/docs/get-started/install))
2. এই ফোল্ডারে টার্মিনাল দিয়ে ঢুকে প্রথমবার শুধু এই কমান্ডটা চালান:
   ```
   flutter create .
   ```
   এটা `android/`, `ios/` ফোল্ডার তৈরি করে দেবে, আমাদের `lib/` কোড অক্ষত থাকবে।
3. এরপর:
   ```
   flutter pub get
   flutter run
   ```
   ফোন USB দিয়ে কানেক্ট করা থাকলে বা এমুলেটর চালু থাকলে অ্যাপ সরাসরি সেখানে ইনস্টল হয়ে চলবে

## Task 2: Database Schema (সম্পন্ন)
`lib/models/medicine.dart` এ দুটো মডেল:
- **Medicine** — নাম, শেলফ, ক্যাটাগরি
- **MedicinePhoto** — একটা মেডিসিনের একাধিক ছবি (front/back/new-packaging), embedding ফিল্ড খালি থাকে যতক্ষণ না Phase 4-এ AI মডেল যোগ হয়

`lib/database/db_helper.dart` এ SQLite টেবিল ও CRUD ফাংশন:
- `medicines` টেবিল ও `medicine_photos` টেবিল (foreign key দিয়ে যুক্ত)
- Insert, search (নাম দিয়ে), update, delete — সব রেডি
- নাম ও শেলফের ওপর index রাখা হয়েছে যাতে সার্চ দ্রুত হয়

এখনো কোনো স্ক্রিন এই ডেটাবেসের সাথে যুক্ত না — Task 3-এ Search screen যুক্ত হবে।

## Task 3: Search Screen ডেটাবেসের সাথে যুক্ত (সম্পন্ন)
`lib/screens/search_screen.dart` এখন সরাসরি `DBHelper.searchMedicines()` কল করে —
টাইপ করা মাত্র রেজাল্ট আপডেট হয় (name LIKE search)। খালি ডেটাবেসে এখন
"কোনো Medicine পাওয়া যায়নি" দেখাবে, যেটা স্বাভাবিক যতক্ষণ না Task 4-এ এন্ট্রি যোগ করা যায়।

## Task 4: Add Medicine ফর্ম ডেটাবেসে সেভ (সম্পন্ন)
`lib/screens/add_medicine_screen.dart` এখন নাম + শেলফ validate করে
`DBHelper.insertMedicine()` দিয়ে সেভ করে, সেভ হলে confirmation দেখায় এবং
ফর্ম রিসেট হয়ে যায় (পরের এন্ট্রি সহজে যোগ করার জন্য)। এখন Task 3-এর
Search screen দিয়ে এই এন্ট্রিগুলো খুঁজে পাওয়া যাবে।

## Task 5: Medicine List/Browse Screen (সম্পন্ন)
`lib/screens/medicine_list_screen.dart` এখন সব এন্ট্রি লিস্ট আকারে দেখায়,
প্রতিটার পাশে Edit ও Delete বাটন আছে। Delete করার আগে confirmation
ডায়ালগ দেখায় (ভুলে ডিলিট এড়াতে)। Edit করলে ডায়ালগে নাম/শেলফ বদলানো যায়।

---
**ফেজ ২ (বেসিক ফিচার) সম্পূর্ণ** — অ্যাপটা এখন ছবি ছাড়াই সম্পূর্ণ ব্যবহারযোগ্য
একটা নাম-শেলফ লুকআপ টুল: Add → Search → List → Edit/Delete সবকিছু
ডেটাবেসের সাথে যুক্ত।

## Task 6: ক্যামেরা ইন্টিগ্রেশন (সম্পন্ন)
`lib/screens/add_medicine_screen.dart` এখন দুই ধাপে কাজ করে:
1. নাম + শেলফ সেভ করলে medicine তৈরি হয় (একটা id পাওয়া যায়)
2. এরপর "ছবি যোগ করুন" সেকশন আনলক হয় — `image_picker` দিয়ে একাধিকবার
   ছবি তোলা যায়, প্রতিটা ছবি অ্যাপের নিজস্ব ফোল্ডারে কপি হয়ে
   `medicine_photos` টেবিলে লিংক হয়ে যায় (থাম্বনেইল সহ, ট্যাপ করে ডিলিট করা যায়)
3. ভিডিও রেকর্ড বাটনও আছে — এখন শুধু ভিডিও ফাইল ক্যাপচার করে, ফ্রেম বের
   করা হয় না (সেটা Task 7-এ যোগ হবে)

## Task 7: ভিডিও থেকে অটো-ফ্রেম এক্সট্র্যাকশন (সম্পন্ন)
`lib/services/frame_extractor.dart` এখন `video_thumbnail` প্যাকেজ দিয়ে
ভিডিওর দৈর্ঘ্য অনুযায়ী সমান দূরত্বে ৮টা ফ্রেম বের করে (শুরু ও শেষের ৫%
বাদ দিয়ে, কারণ ওখানে সাধারণত হাত নড়াচড়া/ব্লার থাকে)। প্রতিটা ফ্রেম
JPEG হিসেবে সেভ হয়ে `medicine_photos` টেবিলে `label: 'video-frame'` সহ
যুক্ত হয়। ভিডিও রেকর্ড করলে এখন একটা প্রগ্রেস ডায়ালগ দেখাবে (প্রসেসিং কয়েক
সেকেন্ড লাগতে পারে), শেষ হলে কতগুলো ছবি যোগ হলো তা জানিয়ে দেবে।

এখন একটা ~১০ সেকেন্ডের ভিডিওতে বক্স ঘুরিয়ে ধরলেই ম্যানুয়ালি ৪ বার ছবি
তোলার বদলে একবারেই ৮টা angle কভার হয়ে যায়।

## Task 8: একাধিক প্যাকেজিং ভার্সন সাপোর্ট (সম্পন্ন)
নতুন স্ক্রিন `lib/screens/photo_manager_screen.dart` — এটাই এখন ছবি/ভিডিও
ক্যাপচারের একমাত্র জায়গা (আগে Add Medicine স্ক্রিনে যে কোড ছিল তা এখানে
সরিয়ে আনা হয়েছে, ডুপ্লিকেট কোড এড়াতে):

- ছবি তোলার আগে **৩টা ভার্সন চিপ** থেকে বেছে নেওয়া যায় — "স্ট্যান্ডার্ড",
  "পুরনো প্যাকেজিং", "নতুন প্যাকেজিং"
- প্রতিটা ছবি সেই লেবেল নিয়ে সেভ হয়, আর স্ক্রিনে ভার্সন অনুযায়ী **গ্রুপ করে**
  দেখানো হয় (কোনটা পুরনো, কোনটা নতুন — আলাদা আলাদা সেকশনে)
- **Add Medicine** থেকে নাম+শেলফ সেভ করলে সরাসরি এই স্ক্রিনে চলে আসবে
- **Medicine List**-এ যেকোনো এন্ট্রিতে ট্যাপ করলেও এই স্ক্রিন খুলবে — মানে
  কোম্পানি পরে প্যাকেজিং বদলালে, পুরনো এন্ট্রি খুঁজে "নতুন প্যাকেজিং" চিপ
  বেছে নতুন ছবি যোগ করা যাবে, পুরনো ছবি মুছে যাবে না

এতে ম্যাচিং ইঞ্জিন (Phase 4) ভবিষ্যতে একই মেডিসিনের একাধিক ভিজ্যুয়াল
ভার্সনের সাথেই মেলাতে পারবে।

## Task 9: Embedding Engine (সম্পন্ন — একটা গুরুত্বপূর্ণ নোট সহ)
**যা প্ল্যান ছিল বনাম যা করা হলো:** আগে প্ল্যানে ছিল TFLite দিয়ে একটা
deep-learning মডেল (MobileNet-এর মতো) ব্যবহার করা। কিন্তু সেই মডেল ফাইল
(কয়েক MB, TensorFlow Hub থেকে ডাউনলোড করতে হয়) — এই ডেভেলপমেন্ট
এনভায়রনমেন্টে ইন্টারনেট অ্যাক্সেস নেই, তাই সেটা ডাউনলোড করা যায়নি।

তাই এখন `lib/services/embedding_engine.dart`-এ **classical computer vision**
পদ্ধতি ব্যবহার করা হয়েছে — কোনো এক্সটার্নাল মডেল ফাইল লাগে না, সম্পূর্ণ
অফলাইনে কাজ করে:
- **Color histogram** — ছবির প্রধান রংগুলো ক্যাপচার করে
- **Brightness grid (6x6)** — লেবেলের টেক্সট/লোগো কোথায় আছে তার মোটামুটি
  আন্দাজ দেয়

দুটো মিলিয়ে প্রতিটা ছবি থেকে ৬০-সংখ্যার একটা "ফিঙ্গারপ্রিন্ট" (vector) বের
হয়, যেটা এখন থেকে প্রতিটা নতুন ছবি/ভিডিও-ফ্রেমের সাথে অটোমেটিক সেভ হচ্ছে।

**সততার খাতিরে বলে রাখা ভালো:** এই পদ্ধতি রং ও মোটামুটি shape দিয়ে
মেলাতে পারবে, কিন্তু আসল deep-learning মডেলের মতো সূক্ষ্ম টেক্সট/লোগো
চিনতে পারবে না। Task 11-এ যখন real মেডিসিনের ছবি দিয়ে টেস্ট করব, তখন
accuracy কম মনে হলে এই একটা ফাইলই বদলে TFLite মডেল বসানো যাবে — বাকি
অ্যাপের কোনো কোড বদলাতে হবে না, কারণ সবাই শুধু `List<double>` vector নিয়ে
কাজ করে, সেটা কীভাবে তৈরি হলো তা নিয়ে না।

## পরের ধাপ (Task 11)
Embedding জেনারেট করে ডেটাবেসে সেভ করার লজিক Task 9-তেই যুক্ত হয়ে গেছে,
তাই Task 10 হবে **similarity search লজিক** — একটা নতুন embedding দিয়ে
ডেটাবেসের সব embedding-এর সাথে তুলনা করে সবচেয়ে কাছেরটা বের করা।

## Task 10: Similarity Search লজিক (সম্পন্ন)
`lib/services/embedding_engine.dart`-এ যোগ হলো:
- **`SimilaritySearch.search()`** — একটা query embedding (যেমন লাইভ ক্যামেরার
  ফ্রেম থেকে বের করা) নিয়ে ডেটাবেসের সব সেভ করা embedding-এর সাথে তুলনা
  করে, cosine similarity স্কোর অনুযায়ী সাজিয়ে সেরা কয়েকটা ম্যাচ ফেরত দেয়
- **`StoredEmbedding`** — ডেটাবেস থেকে পাওয়া `MedicinePhoto` লিস্টকে সরাসরি
  সার্চ-যোগ্য ফরম্যাটে কনভার্ট করার হেল্পার (`fromMedicinePhotos()`)
- **`MatchResult`** — প্রতিটা ম্যাচের ফলাফল (কোন মেডিসিন, কোন ছবি, স্কোর কত)

এটা এখনো UI-এর সাথে যুক্ত না — শুধু "খুঁজে দেওয়ার" লজিক রেডি হলো। পরের
ধাপে (Task 12) লাইভ ক্যামেরা স্ক্রিন থেকে এটা কল করা হবে।

**খেয়াল রাখার বিষয়:** `minScore` (কতটা মিল হলে "ম্যাচ" ধরা হবে) এখন একটা
প্লেসহোল্ডার ভ্যালু — real মেডিসিনের ছবি দিয়ে টেস্ট না করা পর্যন্ত সঠিক
থ্রেশহোল্ড বোঝা যাবে না। Task 11-এ real testing করে এটা টিউন করতে হবে।

## Task 6 এর পর জরুরি একটা কাজ — ক্যামেরা পারমিশন
`flutter create .` চালানোর পর `android/app/src/main/AndroidManifest.xml`
ফাইলে `<application>` ট্যাগের ঠিক আগে এই লাইনগুলো যোগ করুন, নাহলে ক্যামেরা কাজ করবে না:
```xml
<uses-permission android:name="android.permission.CAMERA"/>
<uses-feature android:name="android.hardware.camera" android:required="false"/>
```
